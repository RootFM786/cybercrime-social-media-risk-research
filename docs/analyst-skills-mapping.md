# Analyst Skills Mapping

## How This Research Transfers to Security Analyst Work

| Research Activity | Transferable Security Skill | Analyst Example |
|---|---|---|
| Identifying common cybercrime types | Threat awareness | Recognising phishing, ransomware and social-engineering patterns |
| Analysing user behaviour | Human-risk analysis | Understanding why an alert may have resulted from unsafe user action |
| Comparing awareness with actual controls | Control-gap analysis | Identifying where policy exists but technical enforcement is missing |
| Assessing business impact | Risk prioritisation | Deciding which incidents require faster escalation |
| Reviewing qualitative responses | Evidence interpretation | Extracting useful context from user reports or phishing submissions |
| Producing recommendations | Security communication | Explaining risk and remediation to non-technical stakeholders |

## Example Analyst Scenario

**Situation:** An employee receives a targeted phishing email referencing information from the company's public LinkedIn page.

A useful analyst does more than block the sender.

They should ask:

1. What public information made the lure believable?
2. Did the user click or provide credentials?
3. Were authentication logs or MFA alerts triggered?
4. Are similar messages targeting other employees?
5. Does the organisation need a technical control, awareness intervention, or both?

This connects the human-risk lessons from the research to practical security investigation.
